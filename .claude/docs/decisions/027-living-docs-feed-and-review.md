# 027 · Living documentation is fed while developing and reviewed while validating

**Context.** The user wants each component to document its standard and the styles applicable via props, and wants the AI to base new pages on that documentation while developing so it doesn't make mistakes and keeps things unique. They want the whole process (workflow, rules, skills, decisions) written down and always kept fed.
**Decision.** (1) Before creating a page or component, the AI reads `docs/catalog/components.md` and `docs/catalog/styles.md` and reuses what exists; it only creates a new primitive if none fits, and then documents it in the same change (rule 07). (2) Each component's block in the catalog includes the props table with all possible values and the CSS class each one activates. (3) The review checklist checks that the diff doesn't use restricted native elements or classes outside the component's CSS, and that the catalog and decisions reflect the change. (4) Every new process directive from the user becomes a written rule or standard the same day (rule 11 and the AI's memory).
**Consequences.** `docs-sync.spec.ts` and `vue/no-restricted-html-elements` mechanize this; the rest is the review.
